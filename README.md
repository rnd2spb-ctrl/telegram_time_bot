# Руководство по Telegram-боту учёта рабочего времени

## 1. Роли пользователей

В боте предусмотрены три роли:

- **Владелец (owner)** — определяется по Telegram ID из переменной `OWNER_ID` в файле `.env`. Владелец имеет административные права.
- **Администратор (admin)** — активный сотрудник, которому владелец назначил роль администратора через управление ролями в боте.
- **Сотрудник (employee)** — обычный пользователь. Может отмечать начало и окончание смены, смотреть график и своё отработанное время.

Первый пользователь, который напишет боту, не становится владельцем автоматически.

## 2. Настройка файла .env

В папке проекта должен находиться файл `.env`. Образец настроек находится в `.env.example`.

Если файла `.env` ещё нет:

1. Сделайте копию `.env.example`.
2. Назовите копию `.env`.
3. Заполните необходимые значения.

Основные параметры:

- `BOT_TOKEN` — токен Telegram-бота, полученный у официального бота [@BotFather](https://t.me/BotFather).
- `OWNER_ID` — числовой Telegram ID владельца.

Пример:

```env
BOT_TOKEN=токен_бота
OWNER_ID=123456789
```

Узнать свой Telegram ID можно, например, через [@userinfobot](https://t.me/userinfobot).

**Важно:** файл `.env` содержит секретный токен. Не отправляйте его другим людям и не публикуйте в Git или мессенджерах. Если токен стал известен посторонним, отзовите его через @BotFather и выпустите новый.

## 3. Как определяются права доступа

Проверка прав выполняется по следующим правилам:

1. Если Telegram ID пользователя совпадает с `OWNER_ID`, пользователь получает роль владельца.
2. Для остальных пользователей бот ищет запись в `data/employees.json` по Telegram ID.
3. Запись со статусом `active` и ролью `admin` даёт административные права.
4. Запись со статусом `active` и ролью `employee` даёт права обычного сотрудника.
5. Если статус сотрудника неактивен, доступ запрещается.

Роль и статус из записи сотрудника имеют приоритет над устаревшими полями старого формата. Поле `is_admin` больше не используется для выдачи прав.

Для назначения администраторов не нужен отдельный список Telegram ID в настройках. Администраторы определяются только по роли в `employees.json`, а назначение и снятие роли выполняется владельцем через меню бота.

Перед административными действиями бот повторно проверяет права пользователя, а не полагается только на наличие административных кнопок в меню.

## 4. Добавление сотрудника

Добавлять сотрудников могут владелец и администраторы.

1. Откройте бота под административным аккаунтом.
2. Нажмите «Добавить сотрудника».
3. Введите номер телефона в формате `+79123456789`.
4. Введите ФИО сотрудника.

После добавления сотрудник сможет привязать свой Telegram-аккаунт к записи.

Повторно добавить тот же номер нельзя. Номера сравниваются по цифрам, поэтому варианты `+7...` и `7...` распознаются как один номер.

## 5. Первичная идентификация сотрудника

1. Сотрудник открывает бота и отправляет команду `/start`.
2. Бот предлагает поделиться контактом или ввести номер в формате `+7XXXXXXXXXX`.
3. Можно нажать кнопку «Поделиться контактом» и отправить свой собственный контакт либо ввести номер текстом.
4. Бот проверяет, существует ли такой номер в списке сотрудников.
5. Если номер найден и ещё не привязан к другому Telegram-аккаунту, запись связывается с аккаунтом пользователя.

Отправить нужно именно собственный контакт. Чужой контакт бот не принимает.

Если номер не найден, проверьте его написание или обратитесь к владельцу/администратору, чтобы вас добавили в список сотрудников.

Если номер уже привязан к другому аккаунту или Telegram ID уже связан с другой записью, повторная привязка не выполняется. Нужно обратиться к владельцу.

## 6. Управление сотрудниками и ролями

Владелец и администратор открывают общий пункт **«Редактировать»**. Внутри доступны:

- **Добавить сотрудника** — создать запись по номеру телефона и ФИО.
- **Изменить данные** — изменить ФИО и, при необходимости, номер телефона.
- **Уволить сотрудника** — изменить статус на `dismissed`. Запись и история смен сохраняются; в списке перед ФИО показывается ☠️.
- **Удалить сотрудника** — удалить запись можно только если у сотрудника нет истории смен. Если история есть, используйте увольнение.
- **Удалить ошибочные записи** — удалить только некорректные непривязанные записи. Записи с корректным телефоном или привязанным Telegram ID этой функцией не удаляются.

Администратор может выполнять эти действия со всеми сотрудниками, кроме владельца. Владелец также может управлять сотрудниками.

Назначать и снимать роль администратора может только владелец. Для этого в его меню редактирования есть пункт **«Назначить/снять администратора»**. Администратор не может менять роли, в том числе собственную.

При изменении ФИО, телефона или роли сохраняются остальные данные сотрудника и история смен.

## 7. Главное меню

Состав меню зависит от роли пользователя.

Обычному сотруднику доступны:

- **Начать смену** — отметить начало своей рабочей смены.
- **Закончить смену** — завершить активную смену.
- **График смен** — посмотреть опубликованное расписание.
- **Мое время** — посмотреть учтённое рабочее время.

Владельцу и администратору дополнительно доступны:

- **Редактировать** — открыть управление сотрудниками.
- **Управление графиком** — перейти к назначению смен.
- **Отчет за неделю** и **Отчет за месяц** — получить сводку по закрытым сменам.

Пункт «Редактировать» доступен обеим административным ролям. Различие в том, что только владелец может назначать и снимать права администратора.

Для учёта личных смен пользователю нужна запись сотрудника, привязанная к его Telegram ID. Само наличие административной роли не заменяет такую привязку.

## 8. Хранение данных

Данные хранятся в JSON-файлах в папке `data`:

- `employees.json` — сотрудники, их контакты, Telegram ID, роли и статусы;
- `shifts.json` — начало и окончание фактических смен;
- `schedule.json` — запланированные смены;
- `audit_log.json` — журнал важных действий пользователей.

В журнал действий записываются только успешно выполненные операции: привязка Telegram, добавление, изменение, увольнение и удаление сотрудников, изменение ролей, начало и окончание смен, добавление записей расписания. Для события сохраняются дата и время, Telegram ID и роль инициатора, тип операции, а также целевой сотрудник и дополнительные сведения, когда они применимы.

Журнал создаётся автоматически при первой записываемой операции. Отдельной кнопки просмотра журнала в меню бота пока нет.

Папка `data` содержит локальные рабочие данные и не должна публиковаться в Git. В частности, журнал может содержать ФИО и номера телефонов, поэтому не отправляйте его посторонним.

Увольнение и блокировка не должны использоваться как способ очистки истории: история смен хранится отдельно от статуса сотрудника.

## 9. Если возникла проблема

**Бот сообщает, что владелец не назначен**

- Проверьте, что в `.env` заполнен `OWNER_ID`.
- Укажите именно числовой Telegram ID.
- После изменения настроек перезапустите бота.

**Сотрудник не может пройти идентификацию**

- Проверьте, что его номер заранее добавлен в список сотрудников.
- Убедитесь, что номер введён в формате `+7XXXXXXXXXX` либо отправлен собственный контакт.
- Если номер уже привязан к другому аккаунту, обратитесь к владельцу.

**Администратор видит обычное меню**

- Проверьте, что у его записи в `employees.json` указано `"role": "admin"` и `"status": "active"`.
- Попросите владельца проверить назначенную роль.
- После изменения роли отправьте боту `/start`.

**Бот сообщает о недостатке прав**

- Убедитесь, что пользователь вошёл под правильным Telegram-аккаунтом.
- Для владельца проверьте соответствие Telegram ID значению `OWNER_ID`.
- Для администратора проверьте роль и статус привязанной записи сотрудника.

---

## Краткая памятка

- Владелец задаётся через `OWNER_ID` в `.env`.
- Администраторы назначаются владельцем через управление ролями в боте.
- Сотрудник сначала добавляется администратором, затем привязывает свой Telegram через `/start`.
- Не публикуйте `.env` и папку `data`.
