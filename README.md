# Руководство по Telegram-боту учёта рабочего времени

## 1. Роли пользователей

В боте предусмотрены три роли:

- **Владелец (owner)** — определяется по Telegram ID из переменной `OWNER_ID` в файле `.env`. Владелец имеет административные права.
- **Администратор (admin)** — активный сотрудник, которому владелец назначил роль администратора через управление ролями в боте.
- **Сотрудник (employee)** — обычный пользователь. Может отмечать начало и окончание смены, смотреть график и своё отработанное время.

Первый пользователь, который напишет боту, не становится владельцем автоматически.

## 2. Настройка файла .env

В папке проекта должен находиться файл `.env`. Образец настроек находится в `.env.example`.

Если файла `.env` ещё нет:

1. Сделайте копию `.env.example`.
2. Назовите копию `.env`.
3. Заполните необходимые значения.

Основные параметры:

- `BOT_TOKEN` — токен Telegram-бота, полученный у официального бота [@BotFather](https://t.me/BotFather).
- `OWNER_ID` — числовой Telegram ID владельца.
- `HOURLY_RATE` — почасовая ставка в рублях. Она влияет на расчёт зарплаты в разделе «Мое время» и в недельных/месячных отчётах. В текущем `.env` и образце установлено 167 руб./ч; для изменения укажите своё значение.

Пример:

```env
BOT_TOKEN=токен_бота
OWNER_ID=123456789
HOURLY_RATE=167
```

Узнать свой Telegram ID можно, например, через [@userinfobot](https://t.me/userinfobot).

**Важно:** файл `.env` содержит секретный токен. Не отправляйте его другим людям и не публикуйте в Git или мессенджерах. Если токен стал известен посторонним, отзовите его через @BotFather и выпустите новый.

## 3. Как определяются права доступа

Проверка прав выполняется по следующим правилам:

1. Если Telegram ID пользователя совпадает с `OWNER_ID`, пользователь получает роль владельца.
2. Для остальных пользователей бот ищет запись в `data/employees.json` по Telegram ID.
3. Запись со статусом `active` и ролью `admin` даёт административные права.
4. Запись со статусом `active` и ролью `employee` даёт права обычного сотрудника.
5. Если статус сотрудника неактивен, доступ запрещается.

У каждой записи сотрудника роль хранится в поле `role` (`employee` или `admin`), а состояние — в поле `status` (`active` или `dismissed`).

Администраторы определяются только по роли в `employees.json`; назначение и снятие роли выполняется владельцем через меню бота.

Перед административными действиями бот повторно проверяет права пользователя, а не полагается только на наличие административных кнопок в меню.

## 4. Добавление сотрудника

Добавлять сотрудников могут владелец и администраторы.

1. Откройте бота под административным аккаунтом.
2. Нажмите «Добавить сотрудника».
3. Введите номер телефона в формате `+79123456789`.
4. Введите ФИО сотрудника.

После добавления бот сразу показывает **личную ссылку для входа** вида `https://t.me/<бот>?start=<код>`. Передайте её сотруднику лично или в личном сообщении: по ней он привяжет свой Telegram-аккаунт к записи. Ссылка одноразовая и действует 72 часа.

Повторно добавить тот же номер нельзя. Номера сравниваются по цифрам, поэтому варианты `+7...` и `7...` распознаются как один номер.

## 5. Первичная идентификация сотрудника

Вход выполняется только по одноразовой ссылке. Номер телефона (текстом или контактом) доступа не даёт: его можно узнать, а ссылка известна только тому, кому её передали.

1. Администратор добавляет сотрудника (или нажимает «Редактировать» → «Новая ссылка») и получает ссылку.
2. Администратор передаёт ссылку сотруднику.
3. Сотрудник открывает ссылку и нажимает «Запустить» (Start) в Telegram.
4. Бот проверяет код, привязывает аккаунт к записи и показывает меню. Ранее назначенные смены графика остаются за сотрудником.

Ссылка одноразовая, действует 72 часа; в базе хранится только её хэш. Если ссылка неверна, уже использована, просрочена или сотрудник уволен, бот отвечает одним и тем же сообщением. Если Telegram-аккаунт уже привязан к другой записи, повторная привязка не выполняется.

**Уведомления.** Когда сотрудник вошёл, владелец и активные администраторы (и тот, кто выдал ссылку) получают сообщение: кто вошёл (ФИО записи, телефон, имя, @username и Telegram ID аккаунта). Если вошёл не тот человек, об этом сразу видно. Уведомления приходят тем, кто хотя бы раз открывал бота. Недоставленное уведомление не блокирует вход и отмечается в журнале.

Владелец без записи сотрудника добавляет себя как сотрудника и входит по ссылке так же.

## 6. Управление сотрудниками и ролями

Владелец и администратор открывают общий пункт **«Редактировать»**. Внутри доступны:

- **Добавить сотрудника** — создать запись по номеру телефона и ФИО.
- **Новая ссылка** — выдать новую ссылку для входа активному сотруднику, который ещё не вошёл (старая ссылка перестаёт работать). Нужна, если ссылка просрочена, потеряна, а также для записей, созданных до появления входа по ссылке. В списках сотрудников рядом указано состояние входа. Ссылку для записи с ролью администратора может выдать только владелец; ссылки обычным сотрудникам выдают владелец и администраторы.
- **Отвязать аккаунт** (только владелец) — сбросить привязку Telegram-аккаунта к записи сотрудника: выбрать запись по номеру, подтвердить «1». Старый аккаунт сразу теряет доступ, бот выдаёт новую ссылку входа. Нужна при смене аккаунта или если запись привязал не тот человек. Историю смен (`shifts.json`) отвязка не меняет: она остаётся за прежним Telegram ID; назначенные смены в графике отвязываются от старого аккаунта и привязываются к новому после входа по ссылке.
- **Изменить данные** — изменить ФИО и, при необходимости, номер телефона.
- **Уволить сотрудника** — изменить статус на `dismissed`. Запись и история смен сохраняются; в списке перед ФИО показывается ☠️.
- **Удалить сотрудника** — удалить запись можно только если у сотрудника нет истории смен. Если история есть, используйте увольнение.
- **Удалить ошибочные записи** — удалить только некорректные непривязанные записи. Записи с корректным телефоном или привязанным Telegram ID этой функцией не удаляются.

Администратор может выполнять эти действия со всеми сотрудниками, кроме владельца. Владелец также может управлять сотрудниками.

Администратор может работать и с другими администраторами: изменять их данные, увольнять или удалять их запись при тех же условиях, что и обычными сотрудниками. Только владелец может менять их роли.

Назначать и снимать роль администратора может только владелец. Для этого в его меню редактирования есть пункт **«Назначить/снять администратора»**. Администратор не может менять роли, в том числе собственную.

При изменении ФИО, телефона или роли сохраняются остальные данные сотрудника и история смен.

## 7. Главное меню

Состав меню зависит от роли пользователя.

Обычному сотруднику доступны:

- **Начать смену** — отметить начало своей рабочей смены.
- **Закончить смену** — завершить активную смену.
- **График смен** — посмотреть опубликованное расписание.
- **Мое время** — посмотреть учтённое рабочее время за последние 7 дней и расчётную зарплату по `HOURLY_RATE`.

Владельцу и администратору дополнительно доступны:

- **Редактировать** — открыть управление сотрудниками.
- **Управление графиком** — открыть подменю добавления, изменения и удаления запланированных смен.
- **Отчет за неделю** и **Отчет за месяц** — получить сводку по закрытым сменам, времени и расчётной зарплате каждого сотрудника, а также общей сумме.

В подменю «Управление графиком» доступны:
- **Добавить смену** — выбрать несколько дней текущего месяца, сотрудника, время начала и окончания. Для дней можно ввести список `13,15,17`, диапазон `13-15` или комбинацию `13-15,18,21-22`.
- **Изменить смену** — выбрать существующую запись и заново указать дату, сотрудника и время.
- **Удалить смену** — выбрать запись и подтвердить удаление.
- **Удалить ошибочные смены** — выбрать только некорректные записи. Можно указать номера `1,3,5`, диапазон `1-4` или их комбинацию. Перед удалением бот покажет выбранные записи и попросит подтверждение.

При добавлении и изменении смен дата выбирается номерами дней текущего месяца: `13`, `13,15,17` или `13-15`. При изменении одной смены указывается только один день. Время можно указать целым часом (`9` → `09:00`) или в формате `HH:MM` / `HH-MM` (`9:30`, `9-30`, `18:15`, `18-15`); `24:00` / `24-00` разрешено только как время окончания. Время окончания должно быть позже времени начала. Переход через полночь в расписании пока не поддерживается. Для одного сотрудника нельзя назначить пересекающиеся смены на одну дату.

Назначать смены можно активным сотрудникам с корректным номером телефона, даже если сотрудник ещё не привязал Telegram. Владелец дополнительно может выбрать себя в списке как «Владелец».

Администратор может добавлять, изменять и удалять расписание сотрудников, но не может создавать или изменять смены владельца. Владелец может управлять всеми записями расписания, включая собственные.

Сотрудники видят личное время после привязки Telegram-аккаунта к записи в `employees.json`. Владелец определяется по `OWNER_ID` и может начинать/заканчивать смену и смотреть личное время без отдельной записи в списке сотрудников.

В подсказках выбора показываются фамилия и маркер: `Иванов >` для сотрудника и `Петров (админ) >` для администратора.

Команда `/whoami` выводит Telegram ID, ФИО и роль текущего пользователя.

## 8. Хранение данных

Данные хранятся в JSON-файлах в папке `data`:

- `employees.json` — сотрудники, их контакты, Telegram ID, роли и статусы;
- `shifts.json` — начало и окончание фактических смен;
- `schedule.json` — запланированные смены;
- `audit_log.json` — журнал важных действий пользователей.

Каждая запись `schedule.json` содержит уникальный ID, дату, идентификатор сотрудника, имя для отображения, время начала и окончания, а также сведения о том, кто создал запись. Для обычного сотрудника `employee_id` строится из нормализованного номера телефона; для владельца используется `owner:OWNER_ID`. Telegram ID сотрудника сохраняется отдельно, если сотрудник уже прошёл привязку.

В журнал действий записываются только успешно выполненные операции: выдача ссылки входа (`invite_created`, `invite_reissued`; сам код в журнал не пишется), вход по ссылке (`employee_linked`), добавление, изменение, увольнение и удаление сотрудников, изменение ролей, начало и окончание смен, добавление, изменение и удаление записей расписания. Для события сохраняются дата и время, Telegram ID и роль инициатора, тип операции, а также целевой сотрудник и дополнительные сведения, когда они применимы.

Журнал создаётся автоматически при первой записываемой операции. Отдельной кнопки просмотра журнала в меню бота пока нет.

Папка `data` содержит локальные рабочие данные и не должна публиковаться в Git. В частности, журнал может содержать ФИО и номера телефонов, поэтому не отправляйте его посторонним.

Увольнение и блокировка не должны использоваться как способ очистки истории: история смен хранится отдельно от статуса сотрудника.

## 9. Если возникла проблема

**Бот сообщает, что владелец не назначен**

- Проверьте, что в `.env` заполнен `OWNER_ID`.
- Укажите именно числовой Telegram ID.
- После изменения настроек перезапустите бота.

**Сотрудник не может пройти идентификацию**

- Вход возможен только по личной ссылке; номер телефона не работает.
- Проверьте, что сотрудник добавлен, и выдайте ссылку: «Редактировать» → «Новая ссылка».
- Ссылка одноразовая и действует 72 часа; после использования или просрочки нужна новая.
- Если аккаунт уже привязан к другой записи, обратитесь к владельцу.

**Администратор видит обычное меню**

- Проверьте, что у его записи в `employees.json` указано `"role": "admin"` и `"status": "active"`.
- Попросите владельца проверить назначенную роль.
- После изменения роли отправьте боту `/start`.

**Бот сообщает о недостатке прав**

- Убедитесь, что пользователь вошёл под правильным Telegram-аккаунтом.
- Для владельца проверьте соответствие Telegram ID значению `OWNER_ID`.
- Для администратора проверьте роль и статус привязанной записи сотрудника.

---

## Краткая памятка

- Владелец задаётся через `OWNER_ID` в `.env`.
- Администраторы назначаются владельцем через управление ролями в боте.
- Сотрудник сначала добавляется администратором, затем входит по одноразовой ссылке, которую получает администратор.
- Не публикуйте `.env` и папку `data`.
