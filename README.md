# Авторизация и права доступа

Это руководство объясняет простыми словами, кто может пользоваться ботом, как назначаются владелец и администраторы и как настроить доступ.

## 1. Кто может пользоваться ботом

В боте предусмотрены три уровня доступа:

- **Владелец (owner)** — главный пользователь. Его Telegram ID указывается в настройках. Владелец имеет административные права.
- **Администратор (admin)** — зарегистрированный активный сотрудник, которому владелец назначил роль администратора через меню «Редактировать сотрудника». Он также имеет административные права.
- **Сотрудник (employee)** — обычный пользователь. Он может отмечать начало и окончание своей смены, смотреть график и своё отработанное время.

Первый человек, который напишет боту, **не становится владельцем автоматически**. Владелец назначается заранее в настройках.

## 2. Какие действия доступны

| Действие | Владелец | Администратор | Сотрудник |
|---|:---:|:---:|:---:|
| Начать и закончить смену | Да* | Да* | Да |
| Посмотреть график смен | Да | Да | Да |
| Посмотреть своё отработанное время | Да* | Да* | Да |
| Добавить сотрудника | Да | Да | Нет |
| Назначить или снять права администратора | Да | Нет | Нет |
| Изменить график смен | Да | Да | Нет |
| Получить отчёт за неделю | Да | Да | Нет |
| Получить отчёт за месяц | Да | Да | Нет |

\* Для учёта личных смен и просмотра своего времени нужна привязанная запись сотрудника. Административные права сами по себе такую запись не создают.

## 3. Где находятся настройки

Настройки доступа хранятся в файле **.env** в папке проекта. Рядом находится образец — **.env.example**.

Если файла .env ещё нет:

1. Откройте папку проекта.
2. Найдите файл .env.example.
3. Сделайте его копию.
4. Назовите копию .env — без окончания .example.

В папке должны остаться оба файла: .env.example и .env.

Файл .env содержит секретный токен. Не отправляйте его другим людям и не публикуйте.

## 4. Настройка токена бота — BOT_TOKEN

Токен — это секретный ключ, с помощью которого программа подключается к вашему Telegram-боту.

1. Откройте Telegram и найдите официального бота **@BotFather**.
2. Если прежний токен когда-либо публиковался или попадал к посторонним, отзовите его и выпустите новый.
3. Скопируйте новый токен.
4. Вставьте его в .env после BOT_TOKEN=.

Пример строки:

    BOT_TOKEN=сюда_вставьте_новый_токен

Вместо поясняющего текста вставьте настоящий токен. Не добавляйте к нему кавычки и не оставляйте лишние пробелы.

## 5. Назначение владельца — OWNER_ID

Владелец определяется по числовому Telegram ID. Это не имя пользователя и не номер телефона.

Узнать свой ID можно, например, у бота **@userinfobot** в Telegram.

Скопируйте число и укажите его после OWNER_ID=.

Пример:

    OWNER_ID=123456789

Замените примерное число на свой настоящий Telegram ID.

**Важно:** если OWNER_ID не указан, бот не запустится. Это сделано специально: у работающего бота должен быть явно назначен владелец.

## 6. Назначение и снятие прав администратора

Новые назначения выполняются непосредственно в боте. Редактировать файл .env и перезапускать бота для этого не нужно.

1. Войдите под аккаунтом владельца.
2. Откройте «Редактировать сотрудника».
3. Выберите зарегистрированного активного сотрудника из списка.
4. Подтвердите назначение администратором или снятие административных прав.

Только владелец может менять роли. Администратор не может назначить или снять администратора, в том числе самому себе.

Назначить администратором можно только активного сотрудника, который уже привязал свой Telegram-аккаунт. При смене роли сохраняются его телефон, Telegram ID и история смен.

Параметр ADMIN_IDS оставлен только для совместимости со старыми аккаунтами без записи сотрудника. Для новых назначений используйте меню бота.

## 7. Как проходит первый вход

### Владелец или администратор

1. Откройте бота в Telegram.
2. Нажмите «Запустить» или отправьте команду /start.
3. Бот проверит, совпадает ли ваш Telegram ID с OWNER_ID. Для остальных пользователей бот проверит привязанную запись сотрудника и её роль.
4. Если вы владелец или активный сотрудник с ролью admin, бот подтвердит административный доступ и покажет административное меню.

Например, если в настройках записано OWNER_ID=123456789, пользователь с таким Telegram ID получит права владельца. Даже если его ещё нет в списке сотрудников.

### Обычный сотрудник

1. Откройте бота и отправьте /start.
2. Бот предложит поделиться номером телефона.
3. Нажмите кнопку отправки контакта в Telegram. Отправить нужно **свой собственный контакт**.
4. Бот проверит, есть ли этот номер в списке сотрудников.
5. Если номер найден и ещё не привязан к другому аккаунту, бот свяжет запись сотрудника с вашим Telegram ID.
6. После успешной привязки появится обычное меню сотрудника.

Если номер не найден, обратитесь к владельцу или администратору: сначала вас нужно добавить в список сотрудников.

## 8. Как добавить сотрудника

Добавлять сотрудников могут только владелец и администраторы.

1. Откройте бота под административным аккаунтом.
2. Нажмите «Добавить сотрудника».
3. Введите номер телефона сотрудника.
4. Затем введите его ФИО.
5. После сообщения об успешном добавлении сотрудник сможет пройти привязку по номеру телефона.

Пример:

- Телефон: +79123456789
- ФИО: Иван Иванов

После добавления Иван должен открыть бота, отправить /start и поделиться своим номером через кнопку Telegram.

## 9. Как бот проверяет административные права

Проверка выполняется не только при показе меню. Перед административными действиями бот повторно проверяет, есть ли у пользователя необходимые права.

Например, при добавлении сотрудника проверка выполняется:
- перед началом добавления;
- при вводе номера телефона;
- при вводе ФИО.

При настройке графика проверка повторяется при вводе даты, имени сотрудника и времени смены.

Если прав недостаточно, бот сообщает об отказе, прекращает административный диалог и очищает временные данные. Это не позволяет продолжить действие после потери прав.

## 10. Что изменилось по сравнению со старой авторизацией

В старых записях сотрудников могло быть поле is_admin. Теперь оно **не подтверждает административные права**.

Даже если в старой записи указано is_admin: true, это само по себе не делает пользователя администратором.

Теперь права определяются так:
- владелец — через OWNER_ID;
- администратор или обычный сотрудник — через поле role в записи сотрудника.

Старый ADMIN_IDS учитывается только для совместимости с аккаунтами, у которых ещё нет записи сотрудника. Если у пользователя уже есть запись, его роль и статус в этой записи имеют приоритет. Новых администраторов назначайте через меню «Редактировать сотрудника».

## 11. Если что-то не работает

**Бот не запускается и сообщает, что не задан BOT_TOKEN**

- Проверьте, что файл называется именно .env, а не .env.example или .env.txt.
- Убедитесь, что после BOT_TOKEN= указан действующий токен.
- Проверьте, что в токене нет лишних пробелов.

**Бот сообщает, что владелец не назначен**

- Откройте .env.
- Укажите свой числовой Telegram ID после OWNER_ID=.
- Сохраните файл и перезапустите бота.

**Назначенный администратор видит обычное меню**

- Убедитесь, что сотрудник зарегистрировал свой Telegram-аккаунт.
- Попросите владельца проверить роль сотрудника через «Редактировать сотрудника».
- Отправьте боту /start, чтобы обновить меню после изменения роли.

**Сотрудник не может привязать номер**

- Убедитесь, что администратор предварительно добавил сотрудника.
- Отправьте именно свой контакт через кнопку Telegram.
- Если номер уже привязан к другому аккаунту, обратитесь к владельцу.

**Бот сообщает о недостатке прав**

- Проверьте, совпадает ли Telegram ID с OWNER_ID или есть ли у привязанной записи сотрудника роль admin и статус active.
- Если вы обычный сотрудник, административные действия вам недоступны.

## 12. Важные правила безопасности

1. Не передавайте файл .env другим людям: в нём хранится секретный токен.
2. Не публикуйте токен в Git, мессенджерах, скриншотах и открытых документах.
3. Если токен стал известен посторонним, отзовите его через @BotFather и выпустите новый.
4. Назначайте администраторами только тех сотрудников, которым доверяете.
5. После изменения .env перезапустите бота. Изменения ролей через меню вступают в силу сразу.

## Краткая памятка

- **Кто владелец?** Пользователь, чей ID указан в OWNER_ID.
- **Как добавить администратора?** Владелец открывает «Редактировать сотрудника» и назначает роль активному зарегистрированному сотруднику.
- **Как сотруднику войти?** Отправить /start и поделиться своим контактом после предварительного добавления в список сотрудников.
- **Почему нет административного меню?** Проверьте статус и роль сотрудника. После изменения роли отправьте /start.
- **Где хранится токен?** В файле .env. Никому его не отправляйте.
